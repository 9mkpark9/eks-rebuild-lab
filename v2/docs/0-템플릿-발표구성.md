# 최종 문서 템플릿과 발표 구성 (15분 발표, 목표 14분)

과제 명세의 최종 문서 구성(요약 / ①~④ / 선택 과제 / 회고)과 평가 기준(① 15, ② 20, ③ 35, ④ 20, 문서 구성 10)에 맞춘 틀이다.
단계별 Markdown(1~6)은 작업 기록 원본으로 두고, 제출물은 이 틀의 Notion 문서 하나로 만든다.
**발표 슬라이드 한 장 = 문서의 "한 장 요약" 한 칸**이 되도록 맞췄다. 슬라이드에 쓴 숫자와 그림은 문서의 같은 자리에서 그대로 찾을 수 있다.

## 1. 최종 문서 (Notion) 틀

```
0. 요약
   0.1 워크로드 소개            구성 요소 표 + 앱 화면 1장                         ← 슬라이드 2
   0.2 단계별로 바뀐 것 한눈에   ①→④ 표 (실행 방식·노출·DB·설정·시나리오 결과)     ← 슬라이드 3
   0.3 최종 아키텍처            구성도 (EKS + ALB + EBS, 선택: RDS)                ← 슬라이드 4
   0.4 완성 기준 점검표          ①~④ 의 모든 행: 결과 한 줄 + 근거 링크
   0.5 수업과 다르게 한 것       MetalLB→NodePort, Calico→Flannel, EKS Auto Mode
1~4. ①②③④  (단계마다 같은 틀)
   N.0 한 장 요약               핵심 숫자 3개 + 그림 1장                          ← 그 단계의 슬라이드
   N.1 완성 기준 점검표          명세 문구 | 결과 | 근거(N.3.x)
   N.2 환경                     구성도, 버전, 비밀 값은 가림
   N.3 완성 기준별 구현과 확인   명세의 행과 1:1. 증거 블록 = 명령 + 캡처 + 결과 한 줄
   N.4 문제와 판단 (토글)        증상 → 원인 → 판단 기준 → 후보 ○△× → 고른 방법 → 확인 → 한계
                                문제 장면 캡처와 고친 뒤 캡처를 한 쌍으로
   N.5 한계 / 확인하지 못한 것
5. 선택 과제     수행표(과제 | 결과 | 증거) → 과제마다 명세가 요구한 증거
6. 회고          6.1 겪은 문제와 해결 2건  6.2 직접 구축 vs 관리형
7. 비용과 정리   과금 자원 표, 삭제 순서, 발표 후 "남은 자원 0" 캡처
부록             다시 실행하는 순서, 파일 구조
```

증거 블록 하나:

```
#### 증거: <명세 문구>   (날짜 · 환경)
![](img/shot/<이름>.png)         ← 실제 터미널 화면 캡처. 계정 번호·IP·비밀번호 가림
**결과:** <한 줄>  →  기준 충족
```

## 2. 발표 (14분 + 여유 1분)

한 장에 **숫자 하나, 그림 하나, 말 세 문장**을 기준으로 했다. 시간 합계 14:00.

| # | 슬라이드 | 시간 | 말할 것 | 그림 |
|---|---|---|---|---|
| 1 | 표지 | 0:20 | 무엇을 세 번 옮겼나 | 앱 메인 화면 |
| 2 | 워크로드 소개 | 0:50 | 구성 요소, 데이터 위치, 외부 설정 | 구성 요소 그림, 예약 화면 |
| 3 | 단계별 변화 한눈에 | 0:50 | ① jar → ② 컨테이너 → ③ kubeadm → ④ EKS (+ RDS) | 흐름 그림 |
| 4 | ① 테스트 환경·시나리오 | 0:50 | WSL 2, 같은 시나리오(60 ~ 65항목)를 모든 단계에서 | WSL 빌드·시나리오 캡처 |
| 5 | ② 이미지 빌드 최적화 | 1:00 | 방법을 하나씩 더하며 잰 크기·재빌드 시간 | 사다리 막대그림, `CACHED` 캡처 |
| 6 | ② 컨테이너 실행·배포 | 0:40 | compose healthy, root 아님, ECR `linux/amd64` | compose ps, push 캡처 |
| 7 | ③ 클러스터 구축 | 1:00 | EC2 3대, 필요한 포트만, NodePort·Flannel 을 고른 이유 | kubeadm 구성도, nodes Ready |
| 8 | ③ 무중단 배포 | 1:00 | v0 실패 243 → 0, 원인 셋과 해결 셋 | 문제 장면(503) / 고친 뒤 캡처 |
| 9 | ③ 데이터·설정 | 0:50 | Pod 를 바꿔도 예약 유지, Secret 분리 | 데이터 사라짐 / 유지 캡처 |
| 10 | ③ 노드 장애에서 배운 것 | 1:10 | 300초 → 30초, DNS 몰림, DB 가 노드에 묶임 | 타임라인 그림 |
| 11 | ④ EKS 전환 | 1:00 | EKS 가 대신하는 일, ③에서 바꾼 값 | 비교표 |
| 12 | ④ 노출·데이터 | 0:50 | ALB, StorageClass 직접 생성, Pod 교체 데이터 유지 | EKS 구성도, PVC·Ingress 캡처 |
| 13 | 선택 과제: RDS | 1:00 | 왜 RDS(기준표), 사설 서브넷, 연결 한도 문제 | RDS 구성도, Too many connections → 0 |
| 14 | 선택 과제 + 회고 | 0:50 | 한 것 목록, 직접 구축 vs 관리형 | 표 |
| 15 | 시연 + 비용·정리 | 1:50 | ALB 주소로 예약 등록·조회·수정 (1:30), 삭제 순서 (0:20) | 브라우저 시연 |

시연이 안 될 때를 대비해 15번 뒤에 시연 화면 캡처(앱 화면 7장)를 예비 슬라이드로 둔다. 완성 기준 점검표와 후보 ○△× 표는 질의응답용 예비 슬라이드로 둔다.
