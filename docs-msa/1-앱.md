# ① 앱 — 앱 런타임 테스트

서비스 3개를 컨테이너 없이 JVM 에서 직접 실행해 확인한 기록이다.
이 단계에서 보는 것은 "앱 자체가 맞게 나뉘었는가"다. 웹 서버, 이미지, 쿠버네티스는 아직 없다.

- 테스트한 날: 11월 13일 (처음 확인은 11월 12일)
- 환경: Windows 11, Corretto 21.0.12, Gradle 9.8.1(래퍼), Spring Boot 4.1.1
- 앱이 붙는 MySQL 8.4 와 Redis 7 만 일회용 컨테이너로 띄웠다. 서비스는 `java -jar` 로 직접 실행했다.

## 무엇을 만들었나

AWS 3-Tier 에 배포했던 단일 WAS(`was/`)를 Gradle 멀티 모듈(`msa/`)로 나눴다. `was/` 는 고치지 않았다.

| 모듈 | 맡는 경로 | 들어 있는 것 |
|---|---|---|
| common (라이브러리) | 없음 | 오류 응답, `/health`, `X-Served-By`, 시각 형식, 역할 확인, `SessionUser`, 공통 설정, 버전 헤더, 상태 응답 |
| auth-service | `/api/auth`, `/api/status/auth` | 로그인, 로그아웃, 내 정보 |
| clinic-service | `/api/pets`, `/api/notices`, `/api/slots`, `/api/admin/notices`, `/api/status/clinic` | 반려동물, 공지, 예약 가능 시간, 슬롯 자동 생성 |
| reservation-service | `/api/reservations`, 공지를 뺀 `/api/admin`, `/api/director`, `/api/status/reservation` | 예약, 간호사·원장 화면 |

- 원본 Java 파일 19개 중 시작 클래스를 뺀 18개를 내용 그대로 옮겼다(git 해시로 대조).
- 세 서비스는 서로를 부르지 않는다. 같은 Redis 세션(쿠키 `SESSION`)을 읽고, 같은 MySQL 의 자기 스키마에 자기 계정으로 접속한다.
- 접속 정보는 환경 변수로 받는다. Redis TLS(`REDIS_TLS`)와 DB 연결 수(`DB_POOL_MAX`)도 환경 변수다.

## 어떻게 테스트했나

### 1. 빌드와 자동 테스트

```powershell
cd msa
.\gradlew.bat clean build
```

`build` 는 컴파일, 테스트, 실행 가능한 jar 만들기를 한다. 테스트는 DB 와 Redis 없이 서비스를 실제로 띄워 HTTP 로 확인한다.

### 2. 앱 런타임 테스트

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts\test-app.ps1
```

jar 3개를 포트 18081(auth), 18082(clinic), 18083(reservation)에 띄우고, 웹 서버를 거치지 않고 각 서비스에 바로 요청한다. 끝나면 프로세스와 컨테이너를 지운다.

## 한계

- **슬롯 생성은 시작할 때와 매일 00:05 에만 돈다.** 시작할 때 DB 가 없으면 다음 날까지 다시 시도하지 않는다. 원본 동작 그대로이고 코드를 고치지 않았다. DB 가 뜰 때 14일 치 시드를 넣는 것으로 보완했다.
- **Windows 에서는 종료 처리(graceful shutdown)를 확인하지 못했다.** 테스트가 프로세스를 강제로 끝낸다. 종료 신호를 받아 정리하는 것은 ② 컨테이너 단계에서 확인했다.
- **Redis 가 죽으면 로그인한 사용자의 요청이 500 으로 실패한다.** 원본 코드의 동작이며 고치지 않았다. Windows 에서는 다시 확인하지 않았고 다른 세션의 Linux 기록만 있다.
- **부하를 건 테스트가 아니다.** 기능이 맞는지만 본다.
