# 문서 찾아보기

과제: **컨테이너, Kubernetes 인프라 구축** (개인 캡스톤). 보듬 동물병원 예약 시스템을 로컬 Docker → EC2 에 직접 만든 Kubernetes → EKS 로 세 번 옮긴다.

제출하는 것은 최종 문서 하나다. 나머지는 그것을 채우기 위한 실행 안내와 근거다.

| 단계 | 배점 | 과제가 정한 환경 | 준비된 것 | 실행 |
|---|---|---|---|---|
| ① 워크로드 테스트 환경 | 15 | WSL 2 Ubuntu | `scripts/run-app.sh`, 워크로드 분석, 테스트 시나리오 | 스크립트가 도는지만 미리 확인했다. 제출용 실행은 아직 |

| ③ Kubernetes 전환 | 35 | EC2 3대, kubeadm | `gitops/` 의 `overlays/kubeadm`, `scripts/test-k8s-ops.sh` | **실행 전.** 내 PC 의 클러스터에서 같은 구성만 확인했다 |

## 저장소 구성

| 폴더 | 내용 |
|---|---|
| `was/`, `cfn/`, `deploy/`, `loadtest/` | 중간프로젝트의 AWS 3-Tier 원본. 고치지 않는다 |
| `msa/` | 서비스 3개(Gradle 멀티 모듈), Dockerfile, 웹 서버 설정, DB 초기화 |
| `web/` | 소개 페이지와 예약 화면. 상태 쪽지와 버전 표시를 더했다 |
| `db/` | 스키마와 시드 생성기. 고치지 않고 이미지가 복사해 쓴다 |
| `compose.yaml` | ② 의 실행 구성 |
| `gitops/` | ③ ④ 의 배포 파일 (Kustomize: `base`, `components`, `overlays/kubeadm` · `eks` · `local`) 과 클러스터 준비 파일 |
| `scripts/` | 아래 표 |

| 스크립트 | 단계 | 하는 일 |
|---|---|---|
| `smoke.sh` | ① ② ③ ④ | 테스트 시나리오. 주소만 바꿔 모든 단계에서 쓴다. `--mark` / `--verify` 로 데이터 유지 확인 |
| `run-app.sh` | ① | 소스를 빌드하고 서비스 3개를 jar 로 직접 실행한다 |
| `new-env.sh` | ② | 비밀번호를 무작위로 채운 `.env` 를 만든다 |
| `push-images.sh` | ② ④ | `linux/amd64` 를 확인하고 레지스트리나 ECR 에 올린다 |
| `new-k8s-secrets.sh` | ③ ④ | 클러스터에 Secret 을 만든다. 값은 화면에 나오지 않는다 |
| `test-k8s-ops.sh` | ③ ④ | 다시 배포, 롤링 업데이트와 롤백, Pod 삭제, DB Pod 삭제 뒤 데이터 확인, Recreate 비교 |
| `eks-apply.sh` | ④ | ECR 주소를 넣어 EKS 용 배포 파일을 적용하거나 지운다 |
| `aws-leftovers.sh` | ④ | 요금이 나오는 자원이 남았는지 본다 (읽기 전용) |
| `smoke.ps1`, `test-app.ps1`, `new-env.ps1` | | Windows 에서 개발할 때 쓰던 PowerShell 판 |
