# 로컬 실행

빌드, 실행, 검증 명령을 단계별로 적는다. 1단계 명령은 Linux 와 Windows 11 양쪽에서 실행해 확인했다
(Windows: 11월 12일, Corretto 21.0.12, Gradle 9.8.1, Docker 29.8.2).

## 1단계: 백엔드 빌드

필요한 것: JDK 21. Gradle 은 래퍼(`gradlew`)가 9.8.1 을 내려받는다.

```bash
cd msa
./gradlew build
```

Windows PowerShell:

```powershell
cd msa
.\gradlew.bat build
```

결과물:

| 파일 | 내용 |
|---|---|
| `msa/auth-service/build/libs/vet-auth-1.0.0.jar` | 로그인 (`/api/auth`) |
| `msa/clinic-service/build/libs/vet-clinic-1.0.0.jar` | 반려동물, 공지, 예약 가능 시간, 슬롯 자동 생성 |
| `msa/reservation-service/build/libs/vet-reservation-1.0.0.jar` | 예약, 간호사·원장 화면 |

버전을 바꾸려면 `./gradlew build -Pversion=1.2.0` 처럼 준다. 파일 이름의 버전이 함께 바뀐다.

`build` 는 테스트도 돌린다. 테스트는 DB 와 Redis 없이 서비스를 띄워 맡은 경로, `/health`, 오류 응답 형식을 확인한다.

## 서비스 하나를 직접 실행하기

MySQL(스키마 `db/schema.sql`, 시드 `db/seed.sql`)과 Redis 가 떠 있어야 한다. 2단계에서 docker compose 로 한 번에 띄우는 방법을 더한다.

| 환경 변수 | 뜻 | 기본값 |
|---|---|---|
| `SPRING_DATASOURCE_URL` | MySQL 주소 | `jdbc:mysql://localhost:3306/vet?connectionTimeZone=LOCAL&characterEncoding=UTF-8` |
| `SPRING_DATASOURCE_USERNAME` / `_PASSWORD` | DB 계정 | 없음 (반드시 준다) |
| `SPRING_DATA_REDIS_HOST` | Redis 주소 | 없음 (반드시 준다) |
| `SPRING_DATA_REDIS_PORT` | Redis 포트 | 6379 |
| `SPRING_DATA_REDIS_PASSWORD` | Redis 비밀번호 | 없음 |
| `REDIS_TLS` | Redis TLS 사용 | `true` (TLS 없는 Redis 는 `false`) |
| `DB_POOL_MAX` | 인스턴스 하나의 DB 연결 수 | 10 |
| `SERVER_PORT` | 서비스 포트 | 8080 |

비밀번호는 파일에 적지 말고 실행할 때 환경 변수로만 준다.

```bash
export SPRING_DATASOURCE_USERNAME=vet_app
export SPRING_DATASOURCE_PASSWORD='<DB 비밀번호>'
export SPRING_DATA_REDIS_HOST=127.0.0.1
export REDIS_TLS=false
SERVER_PORT=8081 java -jar msa/auth-service/build/libs/vet-auth-1.0.0.jar
```

한 PC 에서 셋을 함께 띄울 때는 `SERVER_PORT` 를 8081, 8082, 8083 으로 다르게 준다.

## 1단계 검증

세 서비스를 8081(auth), 8082(clinic), 8083(reservation)에 띄운 뒤 확인한 것:

```bash
# 세 서비스 모두 살아 있고 처리한 서버 이름을 붙인다
curl -i http://localhost:8081/health

# auth 에서 로그인해 쿠키를 받는다 (README 의 테스트 계정)
curl -c cookie.txt -H 'Content-Type: application/json' \
  -d '{"loginId":"owner001","password":"test-only"}' http://localhost:8081/api/auth/login

# 같은 쿠키로 다른 서비스를 부른다 — 둘 다 200 이어야 한다
curl -b cookie.txt http://localhost:8082/api/pets
curl -b cookie.txt http://localhost:8083/api/reservations/me
```

확인 결과는 `docs-msa/결정기록.md` 의 1단계 항목에 적었다.

Windows PowerShell 5.1 에서 같은 확인을 할 때 주의할 점:

- `Invoke-WebRequest` 는 `-Headers` 로 준 `Cookie` 를 보내지 않는다. `-SessionVariable` / `-WebSession` 으로 쿠키를 넘긴다.
- 응답에 charset 이 없으면 한글 본문이 깨져 보인다. 화면 표시만 깨지는 것이고 서비스 응답은 UTF-8 이다.
- clinic 은 포트가 열린 뒤에도 몇 초 동안 슬롯을 채운다. 슬롯 수를 확인하려면 로그의 `SlotGenerator` 줄을 기다린다.

이 확인은 2단계의 `scripts/smoke.ps1` 이 대신한다.

## 2단계: 컨테이너로 한 번에 띄우기

필요한 것: Docker Desktop. 명령은 저장소 루트에서 실행한다. 11월 12일 Windows 11, Docker 29.8.2 에서 확인했다.

### 처음 한 번: .env 만들기

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts\new-env.ps1
```

`.env.example` 을 복사해 비밀번호 3개를 무작위 값으로 채운 `.env` 를 만든다. `.env` 는 커밋되지 않는다. 직접 만들려면 `.env.example` 을 `.env` 로 복사하고 `DB_ROOT_PASSWORD`, `DB_PASSWORD`, `REDIS_PASSWORD` 를 영문과 숫자로 채운다.

| `.env` 항목 | 뜻 | 기본값 |
|---|---|---|
| `VERSION` | 이미지 태그 | `1.0.0` |
| `WEB_SERVER` | 웹 서버. `apache` 또는 `nginx` | `apache` |
| `WEB_PORT` | 브라우저로 여는 포트 | `8088` |
| `DB_POOL_MAX` | 서비스 하나의 DB 연결 수 | `5` |

### 빌드하고 띄우기

```powershell
docker compose up -d --build
docker compose ps
```

처음 빌드는 Gradle 과 기반 이미지를 받느라 몇 분 걸린다. 띄운 뒤 브라우저에서 http://localhost:8088 을 연다. 로그인은 README 의 테스트 계정을 쓴다.

컨테이너 6개가 뜬다: `web`, `auth`, `clinic`, `reservation`, `mysql`, `redis`. 밖으로 열린 포트는 `web` 하나뿐이다.

### 검증

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts\smoke.ps1
```

로그인, 예약 신청·조회·취소, 간호사 승인, 원장 일정, 그리고 서비스를 하나씩 멈춘 상태에서 나머지가 되는지를 확인한다. 37개 항목이 모두 `[통과]` 이고 마지막 줄이 `결과: 통과 37, 실패 0` 이면 정상이다. 서비스를 멈추고 켜는 5번을 건너뛰려면 `-Isolation none` 을 붙인다(18개 항목).

### 웹 서버 바꾸기

`.env` 의 `WEB_SERVER` 를 `nginx` 로 바꾸고 web 만 다시 만든다. 다른 컨테이너는 그대로 둔다.

```powershell
docker compose up -d --build web
powershell -NoProfile -ExecutionPolicy Bypass -File scripts\smoke.ps1
```

응답 헤더 `X-Web-Version` 이 `1.0.0-apache` 에서 `1.0.0-nginx` 로 바뀐다. smoke 결과는 같아야 한다.

### 초기 상태로 되돌리기

DB 에는 볼륨이 없다. mysql 컨테이너를 다시 띄우면 스키마와 그날 기준 시드로 돌아간다.

```powershell
docker compose restart mysql
```

### 내리기

```powershell
docker compose down
```

### 이미지 하나만 직접 빌드하기

| 이미지 | 빌드 위치 | 명령 |
|---|---|---|
| 서비스 3개 | `msa/` | `docker build -f auth-service/Dockerfile --build-arg VERSION=1.0.0 -t ghcr.io/9mkpark9/vet-auth:1.0.0 .` |
| web (Apache) | 저장소 루트 | `docker build -f msa/web/Dockerfile.apache --build-arg VERSION=1.0.0-apache -t ghcr.io/9mkpark9/vet-web:1.0.0-apache .` |
| web (nginx) | 저장소 루트 | `docker build -f msa/web/Dockerfile.nginx --build-arg VERSION=1.0.0-nginx -t ghcr.io/9mkpark9/vet-web:1.0.0-nginx .` |
| db | 저장소 루트 | `docker build -f msa/db/Dockerfile -t ghcr.io/9mkpark9/vet-db:1.0.0 .` |

### 막힐 때

- **8088 포트가 이미 쓰이고 있다**: `.env` 의 `WEB_PORT` 를 다른 번호로 바꾼다. 8080 은 PC 에 Apache 가 서비스로 깔려 있으면 이미 쓰이고 있다.
- **compose 가 `.env 에 DB_PASSWORD 가 필요합니다` 로 멈춘다**: `.env` 가 없거나 비밀번호가 비어 있다. `scripts\new-env.ps1` 을 실행한다.
- **스크립트 출력의 한글이 깨진다**: Windows PowerShell 에서 `-File` 로 실행한다. 스크립트가 출력 인코딩을 UTF-8 로 맞춘다.
